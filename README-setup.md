# JNH ER — คู่มือติดตั้ง (โฟลเดอร์ "JNH ER")

ระบบนี้มี 3 ส่วน ใช้ **Firebase โปรเจกต์ใหม่ 1 อัน** ร่วมกัน:

| โฟลเดอร์ | ไฟล์เปิดใช้ | หน้าที่ |
|---|---|---|
| `checklist/` | `index.html` | แอปเช็คของ ER & EMS (หน้า 1–3 + Admin รหัส 1234) |
| `monitor/` | `index.html` | จอ Monitor รวม (Fast Track + EMS + สถานะเช็คของ) |
| `portal/` | `index.html` | **JNH ER** พอร์ทัลรวมทุกแอป (ล็อกอิน + อนุมัติสมาชิก) |
| `firebase-config.js` | — | ค่า config กลาง (แก้ครั้งเดียว ใช้ได้ทั้ง 3 ส่วน) |
| `database.rules.json` | — | rules ของ Realtime Database |

> โฟลเดอร์นี้วางอยู่ใน `whole ER app/` เดียวกับแอปเดิม (Fast Track, EMS, Triage, CPR, รักและใส่ใจ)
> เพื่อให้ Monitor และ Portal ลิงก์ถึงแอปเดิมได้ด้วย path ภายในโฟลเดอร์เดียวกัน

---

## ขั้นที่ 1 — สร้าง Firebase โปรเจกต์ใหม่
1. ไปที่ https://console.firebase.google.com → **Add project** → ตั้งชื่อ เช่น `jnh-er` → สร้าง (ปิด Analytics ได้)
2. เมนูซ้าย **Build → Realtime Database** → **Create database** → เลือก location **Singapore (asia-southeast1)** → เริ่มแบบ *locked mode*
3. แท็บ **Rules** → ลบของเดิม วางเนื้อหาจากไฟล์ **`database.rules.json`** ในโฟลเดอร์นี้ → **Publish**

## ขั้นที่ 2 — เอา config มาใส่
1. Firebase → ⚙️ **Project settings** → หัวข้อ **Your apps** → กดไอคอน `</>` (Web) → ตั้งชื่อ → Register
2. คัดลอกค่าในบล็อก `firebaseConfig = { ... }`
3. เปิดไฟล์ **`firebase-config.js`** แล้ววางทับค่า `apiKey`, `messagingSenderId`, `appId`
   และตรวจว่า `databaseURL`, `projectId`, `authDomain`, `storageBucket` ตรงกับโปรเจกต์จริง
   (ที่สำคัญที่สุดคือ **`databaseURL`** ต้องถูกต้อง)

> ✅ ก่อนตั้งค่า Firebase ทุกแอปยัง **ทดสอบได้** โดยเก็บข้อมูลในเครื่องนั้น ๆ (localStorage)
> จะมีแถบเตือนสีเหลืองบอกอยู่ พอใส่ config แล้วรีเฟรช ระบบจะสลับไปใช้ฐานข้อมูลกลางอัตโนมัติ

## ขั้นที่ 3 — สร้างแอดมินใหญ่ของ Portal
1. เปิด `portal/index.html` → **สมัครสมาชิก**
2. ตั้ง username = **`pettoo`** (ตรงกับ `SUPERADMIN_USERNAME` ใน config) → ระบบจะอนุมัติเป็น **แอดมินใหญ่** ให้อัตโนมัติ
3. คนอื่นสมัครแล้วจะขึ้นสถานะ **รออนุมัติ** จนแอดมินกดอนุมัติในเมนู “👥 จัดการผู้ใช้”

## ขั้นที่ 4 (แนะนำ) — วางออนไลน์
อัปโหลดทั้งโฟลเดอร์ `whole ER app/` ขึ้น GitHub Pages / Netlify / Firebase Hosting
- Checklist:  `.../JNH%20ER/checklist/`
- Monitor:    `.../JNH%20ER/monitor/`   (เปิดเต็มจอบนทีวี ER)
- Portal:     `.../JNH%20ER/portal/`    ← เข้าหน้านี้เป็นหลัก

## หน้าที่ของแต่ละส่วน (ตรงกับที่ขอ)

### 1) Checklist (แอปเช็คของ)
- **หน้าแรก**: หัวข้อ “Check list item available” + บรรทัด **เวร / วันที่ / เวลา** (จริงตามเครื่อง, โซนเวลาไทย)
  เวร: เช้า 08–16 · บ่าย 16–24 · ดึก 00–08 → มีกล่องขอบมนให้ใส่ **“กรุณาใส่ชื่อผู้ทำการตรวจสอบ”**
  ปุ่ม **Admin** มุมขวาบน (รหัสเริ่มต้น **1234** เปลี่ยนได้ในเมนู Admin)
- **หน้าสอง**: โชว์เวร/วันที่ด้านบนเสมอ + เลือกตำแหน่ง 5 ช่อง (Incharge, Nurse aid, EMT, กระเป๋า A/B, กระเป๋า C/D)
  แต่ละช่องโชว์ % ที่เช็คแล้วของเวรนี้
- **หน้าสาม**: ตารางเช็คของ **เฉพาะเวรปัจจุบัน** (ไม่รวมหลายวัน) — ติ๊ก “ครบ” + ช่อง **หมายเหตุ** (ชำรุด/รอซ่อม/อื่น ๆ)
  บันทึกอัตโนมัติทุกครั้งที่ติ๊ก
- รายการ EMT / A-B / C-D ดึงมาจากไฟล์ Excel แล้ว, ส่วน **Incharge & Nurse aid ยังว่าง** → ให้ Admin เพิ่มรายการเองในเมนู Admin (แก้ไข/เพิ่ม/ลบ ได้ทุกตำแหน่ง)

### 2) Monitor รวม
- ซ้าย 70% = ER Fast Track (ฝังหน้า tv.html เดิม ไม่แก้ไขของเดิม)
- ขวาบน = EMS Monitor (ฝังหน้า `#tv` เดิม)
- ขวาล่าง = สถานะเช็คของ 5 ตำแหน่ง เป็น **% รายเวร** ครบ 100% ขึ้น **สีเขียว**
- ปรับสัดส่วน/URL ได้ที่บล็อก `CONFIG` ด้านบนไฟล์ `monitor/index.html`

### 3) JNH ER Portal
- สมัคร → **แอดมินอนุมัติทุกบัญชีก่อนใช้งาน**
- แอดมิน **รีเซ็ต/แก้รหัสผ่าน** ผู้ใช้แต่ละคนได้, ระงับ/เปิดใช้, ตั้ง/ถอดแอดมินร่วม, ลบผู้ใช้
- มี **“จดจำการเข้าใช้งาน”** (auto login ในเครื่องนั้น 30 วัน)
- หน้า “หน้าหลัก” = ปุ่มเข้าทุกแอป (Fast Track, EMS, Triage, CPR, รักและใส่ใจ, Checklist, Monitor)
  แก้/เพิ่มรายการปุ่มได้ที่ตัวแปร `APPS` ด้านบนไฟล์ `portal/index.html`

## ⚠️ หมายเหตุด้านความปลอดภัย
Portal ใช้ระบบล็อกอินที่เก็บใน Realtime Database (รหัสผ่านเก็บแบบ **hash** ไม่ใช่ตัวจริง) เพื่อให้
**แอดมินรีเซ็ตรหัสผ่านเองได้โดยไม่ต้องมีเซิร์ฟเวอร์หลังบ้าน** เหมาะกับใช้ภายในหน่วยงาน
หากต้องการความปลอดภัยสูงขึ้น แนะนำให้จำกัด rules ของ Realtime Database (เช่น ให้เขียน `portal/users`
ได้เฉพาะเงื่อนไขที่กำหนด) หรือย้ายไปใช้ Firebase Authentication + Cloud Functions ภายหลัง
